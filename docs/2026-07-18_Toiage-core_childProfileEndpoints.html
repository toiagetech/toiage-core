The story generation endpoint is fully implemented and tested. Here are the details you asked for:

Endpoint

POST /stories/generate

Summary: Generate a personalized AI story based on parent-selected parameters (goal, mood, length, theme, today's context) and optionally a child profile for personalization. The story is generated via the LLM and persisted to the database in a single call.

Request Body (StoryGenerateRequest)

{
  "goal": "friendship",
  "storyMood": "bedtime",
  "storyLength": "short",
  "theme": "forest",
  "todayContext": "Aria was feeling lonely because her best friend did not play with her today.",
  "childId": 1,
  "provider": "mock",
  "temperature": 0.7,
  "maxTokens": 1024
}
Field Type Required Default Description
goal string ✅ — Learning goal/value the story should teach (e.g. friendship, kindness)
storyMood string ✅ — Mood of the story (e.g. bedtime, adventure)
storyLength string ✅ — Length: short (~100 words), medium (~200), long (~400)
theme string ✅ — Theme/setting (e.g. forest, space)
todayContext string ❌ null Optional context about the child's day
childId int ❌ null Optional child ID for personalization (pulls name, interests, notes)
provider string ❌ "mock" LLM provider: mock, openrouter, or deepseek
temperature float ❌ 0.7 Sampling temperature (0.0–2.0)
maxTokens int ❌ 1024 Max tokens in response (1–8192)

How it works (pipeline)

  1. Optionally loads the Child profile (by childId) for personalization — injects name, nickname, interests, and special notes into the prompt.
  2. Loads the stories/generate.txt prompt template and injects variables.
  3. Prepends the system prompt (tone/safety rules).
  4. Calls the configured LLM provider via llm_manager (defaults to mock — no API key needed).
  5. Parses the title (first line) and content from the LLM response.
  6. Saves the story to the stories table.
  7. Emits the story_generated analytics event.
