CurioPlay — Phase-1 Detailed Backend Development Plan

This document contains the detailed incremental backend execution plan for building the CurioPlay Phase-1 AI platform.

Step-1 — FastAPI Initialization

Goal: Initialize backend project with FastAPI.

  • Create backend project folder.
  • Initialize git repository.
  • Setup uv virtual environment.
  • Install FastAPI and uvicorn.
  • Create minimal app structure.
  • Add /health endpoint.
  • Validate Swagger docs.

Step-2 — Folder Structure + Env Config

Goal: Prepare scalable architecture and environment configuration.

  • Create app modules like api, services, db, prompts and utils.
  • Add .env and .env.example files.
  • Setup centralized config management using Pydantic Settings.
  • Load environment variables safely.
  • Validate config loading during startup.

Step-3 — Database Foundation

Goal: Connect PostgreSQL and setup SQLModel foundation.

  • Install SQLModel and psycopg.
  • Create database session management.
  • Read DATABASE_URL from environment config.
  • Create SQLModel engine.
  • Add database health endpoint.
  • Validate DB connectivity.

Step-4 — Alembic Migration Setup

Goal: Prepare schema migration system.

  • Install Alembic.
  • Initialize migration framework.
  • Configure Alembic with SQLModel metadata.
  • Connect migrations to DATABASE_URL.
  • Create first migration.
  • Validate migration execution.

Step-5 — LLM Abstraction Layer

Goal: Build provider-independent AI architecture.

  • Create LLM provider interface.
  • Add mock provider implementation.
  • Create LLM manager service.
  • Define unified AI response structure.
  • Add test AI endpoint.
  • Validate mock responses.

Step-6 — OpenRouter Integration

Goal: Integrate real AI model support.

  • Create OpenRouter provider.
  • Store API keys securely.
  • Configure Gemini Flash model.
  • Connect provider to LLM manager.
  • Test real AI prompt execution.
  • Add graceful error handling.

Step-7 — Prompt Management System

Goal: Externalize and organize prompts.

  • Create prompts directory structure.
  • Add story/activity prompt templates.
  • Build prompt loader utility.
  • Support dynamic variable injection.
  • Integrate prompt system with AI calls.

Step-8 — Story Generation API

Goal: Build first real business feature.

  • Create story schemas.
  • Add story service and router.
  • Create POST /stories/generate endpoint.
  • Generate child-friendly stories using AI.
  • Return title, content and metadata.

Step-9 — Metadata + Persistence

Goal: Store stories with searchable metadata.

  • Create story database model.
  • Add metadata fields like age, theme and difficulty.
  • Create DB migration.
  • Persist generated stories.
  • Add story retrieval APIs.

Step-10 — Activity Generation Feature

Goal: Convert stories into practical activities.

  • Create activity schemas and services.
  • Build activity generation endpoint.
  • Generate household and kit-based activities.
  • Provide materials list and steps.
  • Save activities into database.

Step-11 — Image Upload Foundation

Goal: Allow parents to upload child creations.

  • Create upload API.
  • Validate uploaded images.
  • Store images locally initially.
  • Return accessible image URLs.
  • Prepare upload metadata structure.

Step-12 — AI Image Reflection

Goal: Generate positive AI reflections on uploads.

  • Integrate vision-capable AI model.
  • Analyze uploaded images.
  • Generate encouraging feedback.
  • Ask curiosity-based follow-up questions.
  • Maintain child-safe tone.

Step-13 — Logging + Error Handling

Goal: Improve backend stability and debugging.

  • Add structured logging.
  • Track API requests and AI calls.
  • Add centralized exception handling.
  • Handle AI failures gracefully.
  • Add timeout management.

Step-14 — Analytics Foundation

Goal: Track product engagement metrics.

  • Create analytics service abstraction.
  • Track story/activity/upload events.
  • Prepare PostHog integration.
  • Capture engagement metrics cleanly.

Step-15 — Phase-1 Stabilization

Goal: Prepare backend for frontend integration.

  • Clean project structure.
  • Remove dead code.
  • Add README and setup instructions.
  • Validate all APIs and migrations.
  • Add sample curl requests and basic tests.
